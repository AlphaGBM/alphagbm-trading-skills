# AlphaGBM 总路由

## 何时触发

用户提出研究标的、财报解释、事件归因、估值、交易复盘、持仓记录、交易能力训练或恢复历史上下文时触发。

## 首轮协议

识别 `/gbm`、显式选中的 `gbm` 或“使用 gbm”请求后，先读任务意图而非逐字匹配前缀。只给入口、不附任务时，简短询问“想做财报归因、公司研究，还是复盘自己的决策？”，不要擅自联网或运行所有分支。不要把机器学习的 GBM 问题路由进金融研究。

1. 复述目标、标的、市场、时间窗和用户希望的交付物。
2. 先判断是在“向外研究”（`gbm-research`）、“解释事件”（`gbm-event-attribution`）、“做模型”（`gbm-model`）还是“复核自己的决策”（`gbm-diagnosis` / `gbm-trade`）。
3. 说明数据是否实时、是否一手、是否只读；缺数据就降级，不猜。
4. 输出中分开 `FACT`、`MANAGEMENT`、`MARKET`、`MODEL`、`INFERENCE`、`UNKNOWN`。
5. 任何买卖方向问题先做证据与风险复核，不直接给出下单指令。

“现在买还是卖”“该不该加仓”这类方向请求，即使只给了公司名，也先进入 `gbm-diagnosis`：索取目标、持有周期、风险预算、当前计划和失效条件；只有在诊断后仍需要研究事实时，才转 `gbm-research` 或 `gbm-event-attribution`。不能因为用户说了一个标的就先走公司研究。

## 路由表

| 需求 | Skill |
|---|---|
| 财报、公告、电话会后股价异动 | `gbm-event-attribution` |
| 标的/行业/主题研究 | `gbm-research` |
| 公开行情或公司基本面数据 | `gbm-market-research` |
| 估值、情景、压力测试 | `gbm-model` |
| 报告写作与证据索引 | `gbm-report` |
| 个人交易计划、持仓、成交复盘 | `gbm-trade` |
| 判断是否有证据支持 | `gbm-diagnosis` |
| 概念和指标解释 | `gbm-deconstruct` |
| 对标和方法比较 | `gbm-benchmark` |
| 交易能力练习 | `gbm-coach` |
| 保存/恢复记录 | `gbm-save` / `gbm-restore` |

## 短句分流

- “财报后为什么跌”“解释公告异动” → `gbm-event-attribution`；缺标的或事件时间先补信息。
- “研究公司”“行业竞争怎样” → `gbm-research`；“我的判断哪里错”“买还是卖” → `gbm-diagnosis`，不是同一入口。
- “估值”“三情景” → `gbm-model`；事件＋模型复合请求先核验证据，再传入模型，不直接把市场叙事当假设。
- “写报告” → `gbm-report`；“保存这份报告”才进入 `gbm-save`，研究结束不构成写入授权。
- “继续上次”“恢复昨天记录” → `gbm-restore`，先确认记录路径与截止时点。

路由后加载对应目录的 `SKILL.md`；目标未安装时如实提示缺少该技能，不声称已调用，也不自动安装。使用宿主提供的技能调用机制；这些名称不代表 shell 命令或网络 API。

## 失败处理

如果来源冲突、行情不可得、事件时间不明确或记录缺失，先列出缺口和最小补证动作，不用更强的语气掩盖不确定性。
