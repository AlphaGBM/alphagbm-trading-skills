# 财报与事件归因协议

## 目标

解释“事件发生后，市场为什么这样定价”，而不是证明一个漂亮故事。输出必须区分：事件事实、预期差、价格反应、替代解释和仍未解决的问题。

## 五层流程

1. **锁定事件**：公司、证券、事件类型、公告时间、财报期和市场时区；保存公告原文版本。
2. **建立预期**：记录事件前可观察的共识、公司指引、管理层前次承诺、关键经营指标和市场定位；不能用事件后修订的数据替代当时预期。
3. **拆解信息冲击**：分别核对收入、利润、现金流、分部、用户/出货/订单、毛利、指引、资本配置、风险措辞和电话会新增信息。
4. **测量反应**：定义事件窗口和基准，计算绝对收益、相对收益、成交量/波动率变化，并记录窗口内的宏观、行业、同业和技术面混杂因素。
5. **形成归因**：按证据强弱排序主要驱动，写出至少一个反事实或替代解释，并给出后续可验证指标。

## 推荐窗口

- 即时：公告后 30 分钟或下一可交易时段，用于观察首次价格发现。
- 短期：`[t0, t+1]`、`[t0, t+5]` 交易日，用于观察信息吸收。
- 中期：`[t0, t+20]` 交易日，用于观察趋势是否由基本面持续验证。

窗口必须根据市场、时区、盘前/盘后和公告可得性调整；没有行情数据就只做定性归因，不虚构收益数字。

## 归因模板

```text
事件：
事件时点：
核心事实（仅一手来源）：
事件前预期：
实际披露与预期差：
管理层新增信息：
市场反应与基准：
主要解释（证据）：
替代解释（证据/缺口）：
置信度：高 / 中 / 低
可证伪条件：
下一次验证时间与指标：
```
